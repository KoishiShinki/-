# 发布检查清单

本清单供项目维护者在合并变更或发布版本前使用。公开仓库只应包含源码、配置模板、数据库结构、测试和必要文档。

## 文件与配置

- [ ] 待提交文件不包含真实账号、密码、AI 密钥、数据库转储、用户上传内容或私人作品。
- [ ] `.env`、上传目录、日志、编辑器配置、依赖目录和构建产物未加入 Git。
- [ ] `.env.example` 只包含空值、占位符或公开默认地址；前端变量中没有服务端密钥。
- [ ] 测试使用合成数据，新加入的图片、字体与文档具有明确的再分发许可。
- [ ] 检查图片元数据和文本导出中的个人信息；自动扫描不能替代人工复核。
- [ ] 对意外公开的密钥及时撤销并重新签发；删除文件或改写历史不能使旧密钥失效。

## 验证与兼容

- [ ] 按 [开发指南](DEVELOPMENT.md) 运行后端测试、前端测试与生产构建。
- [ ] 数据库结构变更附有迁移方案，并在临时数据库中验证。
- [ ] 检查管理员权限、私有内容隔离和公开阅读范围。
- [ ] AI 保持默认关闭；服务接入测试在私有环境使用专门的测试配置。
- [ ] 保留项目及第三方组件所需的 LICENSE、版权和 NOTICE 声明。

## Git 与发布

在仓库根目录执行：

```sh
python scripts/test_release_check.py
python scripts/release_check.py
git diff --check
git diff --cached --check
```

随后人工检查待提交文件与 diff。工作树扫描不会检查旧提交，涉及外部代码导入或历史变更时还需检查引入的 Git 历史。不要把另一个项目的分支、标签或完整 `.git` 目录导入发布仓库。

提交说明使用中文。发布前确认目标提交的 GitHub Actions 已通过，并确保版本说明准确描述对使用者的影响。仓库可按需要启用秘密扫描、推送保护和依赖告警。

生成只包含可发布源码的压缩包：

```sh
python scripts/package_release.py --output ../chronicle-studio-source.zip
```

输出路径必须在源码目录之外。脚本先执行发布检查，再打包通过检查的源文件，排除 Git 历史、依赖目录和编译产物。扫描通过仅表示未命中规则，不代表已经覆盖所有安全或隐私问题。
