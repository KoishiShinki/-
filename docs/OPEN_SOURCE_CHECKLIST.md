# 开源发布检查

只发布经过检查的 Chronicle Studio 源代码目录。旧项目保留为本地参考，不能整目录上传。

## 文件与配置

- [ ] 仅包含源代码、配置模板、纯结构数据库迁移、测试、构建文件和维护文档。
- [ ] 不包含旧 `.git` 历史、数据库转储、真实账号、用户记录、上传内容、日志、截图、课程报告、编辑器配置和构建产物。
- [ ] 密码、会话密钥、AI 密钥通过服务器环境变量提供；`.env.example` 仅有占位符。前端变量中不得放服务器密钥。
- [ ] 对曾经提交、分享或公开过的真实密钥，在服务商后台撤销并重新签发。删除文件或建立新仓库不会撤销旧密钥。
- [ ] 检查图片元数据、测试样例、CSV/JSON 导出以及配置占位符的默认值；自动扫描无法覆盖所有敏感信息。

## 功能与许可

- [ ] 完成 README 指定的后端测试与前端构建，按迁移文档核对原功能。
- [ ] 核对项目 LICENSE、THIRD_PARTY_NOTICES.md 和 licenses/RuoYi-MIT.txt；保留 RuoYi 原有 MIT 归属声明。
- [ ] 新增图片、字体、文档、演示数据均有明确的再分发许可；演示数据必须是合成数据。
- [ ] AI 默认关闭；真实服务接入仅在本地配置，用独立测试账号验证。

## GitHub 发布

1. 在准备好的发行目录运行 `python scripts/release_check.py`，处理全部发现，并人工复核待提交文件。
2. 完成验证后，在该发行目录建立全新的 Git 历史；不要复制旧 `.git`，也不要推送旧分支或标签。
3. 在首次提交前检查 `git status --short` 与 `git diff --cached`；确保本地配置和运行数据未进入暂存区。
4. 确认仓库名称、归属和公开范围后创建 GitHub 仓库，再推送这一份新历史。未完成这些检查前不要发布。
5. 按需启用 GitHub 的秘密扫描、推送保护、依赖告警和私密漏洞报告；阅读 SECURITY.md。

发行包可使用 `python scripts/package_release.py --output ../chronicle-studio-source.zip` 生成。扫描通过仅表示未命中已知规则，不代表完成全部安全或隐私审查。
