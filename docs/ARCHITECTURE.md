# Chronicle Studio 架构

本项目将世界线业务从原有通用后台框架中拆出。后端单独构建为 Spring Boot 应用，前端保留 Vue 3；构建和运行不需要若依模块、若依菜单路由、若依权限表达式或 Redis 登录缓存。

## 模块边界

经确认，迁移范围仅包含世界线、AI 叙事及其管理后台。原若依附带的用户/角色/菜单/部门、字典、定时任务和代码生成等通用模块不属于本次保留范围。

- **公开阅读**：读取已公开世界线、已发布章节、已采用插图和创作者公开资料。
- **创作工作台**：在服务端校验所属世界线后，管理截图、事件、事件关系、阶段、国家状态、人物、章节和插图。
- **业务管理**：管理员管理世界线内容及 AI 任务。客户端导航不承担权限校验职责。
- **认证与存储**：独立账户、密码哈希、可撤销会话和文件访问边界。
- **AI 适配器**：文本、视觉与图片生成由服务端访问兼容提供方。接口密钥通过环境变量注入。

## 数据与接口兼容

保留世界线 `tl_*` 业务字段和主要 `/public`、`/app`、`/timeline` 路由，使迁移可以逐项核对功能。常规响应使用 `{code,msg,data}`，分页列表使用 `{code,msg,rows,total}`。前端开发代理将 `/api` 前缀剥离后转发至后端。

身份数据与旧框架表分离。迁移业务数据时必须保持用户编号、用户名以及各业务记录之间的编号对应关系；`create_by` 是原业务的归属依据，不能在迁移中随意重命名用户。

## 前端设计与性能

前端按阅读、创作和管理工作流组织。请求统一处理认证和错误，页面在需要时加载。互相独立的请求可并行执行，重复读取使用共享缓存；提交后的缓存刷新与实际资源对应，避免整个应用重复请求。

设计与 React 性能指导在本次重构会话中临时读取。根据用户选择，保留 Vue，仅借鉴请求并行、按需加载、避免重复请求等适用原则，不应用 React 专用 API。两个 skill 未安装全局，也不作为应用运行依赖随项目分发。

## 开源隔离

发布项目由经过审阅的源代码和纯结构 SQL 组成，不携带原仓库的 Git 历史、数据库内容、账号、上传素材、截图、课程报告或本地运行配置。上游许可另行保留。
