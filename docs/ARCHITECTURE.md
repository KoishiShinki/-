# Chronicle Studio 架构

Chronicle Studio 是面向世界线创作与阅读的独立应用。前端使用 Vue 3，后端使用 Spring Boot，并通过 HTTP API 通信。

## 模块边界

- **公开阅读**：读取已公开的世界线、已发布章节、已采用插图和创作者公开资料。
- **创作工作台**：服务端校验资源归属后，管理截图、事件、事件关系、阶段、国家状态、人物、章节和插图。
- **业务管理**：管理员管理世界线内容及 AI 任务。客户端导航不承担权限校验职责。
- **认证与存储**：独立账户、密码哈希、可撤销会话和受控的文件访问。
- **AI 适配器**：后端访问兼容提供方，支持文本、视觉和图片生成；密钥通过服务端环境变量配置。

## 数据与接口

应用保留世界线业务 `tl_*` 表及主要 `/public`、`/app` 和 `/timeline` 路由。常规响应使用 `{code,msg,data}`，分页列表使用 `{code,msg,rows,total}`。前端开发代理会移除 `/api` 前缀，再将请求转发至后端。

身份数据与旧框架表分离。迁移业务数据时应保持用户编号、用户名以及业务记录之间的编号关系；`create_by` 用于标识原业务记录的所有者，应与迁移后的用户名对应。

## 前端组织

前端按阅读、创作和管理工作流组织。请求层统一处理会话和错误，路由按需加载页面；独立请求可以并行执行，重复读取会合并处理，提交后的页面只刷新相关资源。

## 发布内容

发行包应仅包含应用源代码、结构定义和必要的构建文件，不应包含数据库内容、账号凭据、上传素材、截图、个人配置或旧项目 Git 历史。第三方组件的许可信息随项目保留。
